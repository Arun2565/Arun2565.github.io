Underlyne
A highlight and underline browser extension. Fully client-side, no backend. Annotations persist across sessions using Chrome storage.
JavaScript Chrome API Browser Extension
What it is

A browser extension for highlighting and underlining web content. Fully client-side, no backend. Annotations persist across sessions using Chrome storage. Built for people who read on the web and want their notes to stay.

Select any text on any webpage, choose a highlight color or underline style, and your annotation is saved. Close the tab, come back a week later — your highlights are still there.

How I built it

Extension Architecture: Chrome Extension Manifest V3 with a content script that injects into every page. Background service worker for handling storage operations and cross-tab communication.

Text Selection: Uses the Range API to capture selected text positions. Stores annotations as serialized ranges with surrounding context (50 characters before and after) for re-anchoring on page reload.

Persistence: Chrome storage.local for persistence with a sync fallback. storage.local offers more quota (100KB vs 100KB for sync), but sync enables cross-device synchronization for users signed into Chrome.

UI: Custom popup interface for selecting highlight colors and viewing all annotations. Minimal design that doesn't interfere with the reading experience.

What failed & where it broke
  • Serialized ranges break on dynamic content: SPAs and infinite scroll pages change DOM structure after initial load. Annotations would highlight wrong text or nothing at all. Had to implement a re-anchoring algorithm that uses surrounding context to find the original text.
  • Chrome storage.local 100KB quota: Heavy readers hit this limit within weeks. Each annotation stores the selected text, surrounding context, color, and metadata. Had to implement compression and an export/import feature.
  • Content script injection timing: Running before DOM ready meant missing annotations on page load. Had to implement a mutation observer that waits for content to stabilize before re-anchoring.
  • Cross-origin iframes: Academic papers embedded in iframes couldn't be annotated due to extension security model. No clean workaround — this remains a limitation.
What I learned
DOM anchoring is harder than it looks. Text-based re-anchoring with surrounding context is more reliable than offset-based positioning, but still breaks on dynamic sites. Sometimes the web just wasn't built for this. The most robust solution is storing enough context to find the text again, not storing positions that will become invalid.
